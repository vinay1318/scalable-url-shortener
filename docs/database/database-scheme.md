
# Database Schema

## Overview

The URL Shortener Service uses MySQL as the primary persistent data store.

The `url_mapping` table stores the relationship between a generated short code and its corresponding destination URL.

---

## Table: `url_mapping`

### Purpose

Stores URL mappings used by the URL shortener.

Each short code uniquely identifies one destination URL. A single destination URL may have multiple short codes, allowing different short URLs to be created for the same destination.

### Schema

| Column | Data Type | Constraints | Description |
|---|---|---|---|
| `id` | `BIGINT` | `PRIMARY KEY`, `AUTO_INCREMENT`, `NOT NULL` | Unique identifier generated by MySQL. The ID is used to generate the Base62 short code. |
| `short_code` | `VARCHAR(16)` | `UNIQUE`, nullable during creation | Base62-encoded short code. The column uses case-sensitive comparison because uppercase and lowercase Base62 characters represent different values. |
| `long_url` | `VARCHAR(2048)` | `NOT NULL` | Original destination URL. Multiple records may contain the same destination URL. |
| `expires_at` | `DATETIME` | `NULL` allowed | Date and time when the short URL expires. `NULL` means the URL does not expire. |
| `created_at` | `DATETIME` | `NOT NULL`, `DEFAULT CURRENT_TIMESTAMP` | Timestamp when the URL mapping was created. |
| `updated_at` | `DATETIME` | `NOT NULL`, `DEFAULT CURRENT_TIMESTAMP`, automatically updated | Timestamp of the most recent modification to the mapping. |

---

## Constraints

### Primary Key

`id` is the primary key and is automatically generated by MySQL.

The generated ID is used as the input to the Base62 encoder.

Example:

```text
MySQL ID: 125
     ↓
Base62 Encoder
     ↓
Short Code: cb
```

### Short Code Uniqueness

`short_code` has a `UNIQUE` constraint.

Although the application generates short codes from unique database IDs, the database constraint provides an additional layer of data-integrity protection.

Because Base62 is case-sensitive:

```text
abc != ABC
```

the `short_code` column must use case-sensitive comparison.

### Destination URL

`long_url` is not unique.

The system intentionally allows multiple short codes to reference the same destination URL.

Example:

```text
abc → https://example.com/product
def → https://example.com/product
ghi → https://example.com/product
```

This allows separate short URLs to be used for different campaigns, expiration policies, or analytics.

---

## Indexes

### Primary Key Index

The primary key on `id` automatically provides an index.

### Short Code Index

The `UNIQUE` constraint on `short_code` provides a unique index.

This supports efficient redirect lookups such as:

```sql
SELECT *
FROM url_mapping
WHERE short_code = 'abc';
```

A separate index on `short_code` is therefore not required.

### Expiration Index

An explicit index is created on `expires_at`.

```sql
CREATE INDEX idx_expires_at
ON url_mapping (expires_at);
```

This supports efficient identification of expired URL mappings for expiration and cleanup operations.

### Long URL

No index is currently required on `long_url` because the primary redirect lookup is performed using `short_code`.

---

## URL Creation Transaction

The short code is generated from the MySQL-generated ID.

The creation process is:

```text
BEGIN TRANSACTION
        ↓
Insert URL mapping
        ↓
MySQL generates ID
        ↓
Generate Base62 short code from ID
        ↓
Update mapping with short code
        ↓
COMMIT
```

Because the ID does not exist until the initial insert occurs, `short_code` temporarily allows `NULL` during URL creation.

The entire operation will be executed transactionally. If short-code generation or the subsequent update fails, the transaction is rolled back so that an incomplete URL mapping is not committed.

## Initial SQL Schema

```sql
CREATE TABLE url_mapping (
    id BIGINT NOT NULL AUTO_INCREMENT,

    short_code VARCHAR(16)
        CHARACTER SET ascii
        COLLATE ascii_bin
        UNIQUE,

    long_url VARCHAR(2048) NOT NULL,

    expires_at DATETIME NULL,

    created_at DATETIME NOT NULL
        DEFAULT CURRENT_TIMESTAMP,

    updated_at DATETIME NOT NULL
        DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,

    PRIMARY KEY (id),

    INDEX idx_expires_at (expires_at)
);
```

## Design Summary

```text
id
├── BIGINT
├── Primary Key
├── Auto Increment
└── Used for Base62 generation

short_code
├── VARCHAR(16)
├── Unique
├── Case-sensitive
└── Indexed through UNIQUE constraint

long_url
├── VARCHAR(2048)
├── Not Null
├── Duplicate destination URLs allowed
└── No index currently required

expires_at
├── DATETIME
├── Nullable
└── Explicitly indexed

created_at
├── DATETIME
└── Automatically populated on creation

updated_at
├── DATETIME
└── Automatically updated when the row changes
```
